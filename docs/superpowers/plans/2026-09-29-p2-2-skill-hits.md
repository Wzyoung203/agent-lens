# P2.2 Skill 命中统计 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 识别「加载某个 skill」的工具调用，统计每个 skill 被加载的次数与它带来的说明文本体量，并在「上下文成本」页呈现。

**Architecture:** 新增 `skills.py` 纯识别层（从工具调用参数里抽出 `SKILL.md` 路径 → skill 名），`analyze` 命令顺带写 `skill_hits` 表（schema v5），查询层 + `/api/skills` 暴露聚合，前端在既有「上下文成本」页加一张表。**不新建页面**——设计文档 9.1 把 skill 命中明细放在上下文成本页里。

**Tech Stack:** Python 3.12、SQLite、FastAPI、pytest、Vue 3 + Element Plus、uv。

**Spec:** `docs/superpowers/specs/2026-09-24-agent-lens-design.md`（6.8 skill 命中、9.1 上下文成本页）

**Depends on:** P2.1（复用 `agent-lens analyze`、`web/src/views/ContextView.vue`）

## Global Constraints

- 与 P2.1 相同：事实源只读、正文不入库、幂等、UTC aware、标识符英文 / 注释中文。
- 不新增运行期依赖。
- **有意收窄的范围**：设计文档 6.8 提到「加载后该轮的成本变化」。本计划**不做**——那需要一个可验证的因果
  模型，而同一轮里 skill 加载与其它工具调用混在一起，现有数据分不出因果。只做可被数据直接支撑的三项：
  加载次数、说明文本体量、覆盖的会话数。这条取舍必须写进 ledger，不要静默跳过。

```python
# src/agent_lens/skills.py
"""识别「加载 skill」的工具调用（设计文档 6.8）。

实测：skill 加载表现为 exec_command / spawn_agent 的参数里出现
`.../skills/<name>/SKILL.md` 路径。只做纯识别，不读文件、不写库。
"""

from __future__ import annotations

import json
import re
from collections.abc import Iterable
from dataclasses import dataclass
from pathlib import Path

SKILL_PATH_RE = re.compile(r"(?P<path>[\w./~+-]*/skills?/(?P<name>[\w.+-]+)/SKILL\.md)")


@dataclass(frozen=True)
class SkillHit:
    file_path: str
    ordinal: int
    skill_name: str
    skill_path: str
    tool_name: str


def _arguments(payload: dict) -> str:
    parts: list[str] = []
    for key in ("arguments", "input", "parameters"):
        value = payload.get(key)
        if isinstance(value, str):
            parts.append(value)
        elif isinstance(value, dict):
            parts.append(json.dumps(value, ensure_ascii=False))
    return "\n".join(parts)


def find_skill_hits(lines: Iterable[str], *, file_path: str) -> list[SkillHit]:
    hits: list[SkillHit] = []
    for line in lines:
        try:
            row = json.loads(line)
        except json.JSONDecodeError:
            continue
        if not isinstance(row, dict) or row.get("type") != "response_item":
            continue
        payload = row.get("payload")
        if not isinstance(payload, dict):
            continue
        if payload.get("type") not in ("function_call", "custom_tool_call"):
            continue
        ordinal = row.get("ordinal")
        if not isinstance(ordinal, int):
            continue
        text = _arguments(payload)
        seen: set[str] = set()
        for match in SKILL_PATH_RE.finditer(text):
            name = match.group("name")
            if name in seen:
                continue
            seen.add(name)
            hits.append(
                SkillHit(
                    file_path=file_path,
                    ordinal=ordinal,
                    skill_name=name,
                    skill_path=match.group("path"),
                    tool_name=str(payload.get("name") or ""),
                )
            )
    return hits


def find_skill_hits_in_file(path: Path) -> list[SkillHit]:
    with path.open("r", encoding="utf-8", errors="replace") as handle:
        return find_skill_hits(handle, file_path=str(path))
```

```python
def write_skill_hits(conn: sqlite3.Connection, rows: Sequence[SkillHit]) -> int:
    """写入 skill 命中。幂等：同 (file_path, ordinal, skill_name) 覆盖不新增。"""
    if not rows:
        return 0
    payload = [
        (row.file_path, row.ordinal, row.skill_name, row.skill_path, row.tool_name, None, None)
        for row in rows
    ]
    with conn:
        conn.executemany(
            """
            INSERT INTO skill_hits (
                file_path, ordinal, skill_name, skill_path, tool_name, session_id, turn_id
            ) VALUES (?, ?, ?, ?, ?, ?, ?)
            ON CONFLICT (file_path, ordinal, skill_name) DO UPDATE SET
                skill_path = excluded.skill_path,
                tool_name = excluded.tool_name
            """,
            payload,
        )
    return len(payload)
```

> 说明：`session_id` / `turn_id` 先留空（工具调用行本身不带这两个字段，硬猜会污染数据）。
> 查询时通过 `(file_path, ordinal)` 关联 `tool_calls` 表拿到 `session_id` / `turn_id`——
> `tool_calls` 主键正是 `(file_path, ordinal)`。这一点在 Task 3 的 SQL 里落地。

```python
class SkillStat(BaseModel):
    skill_name: str
    loads: int
    session_count: int
    tool_names: list[str] = Field(default_factory=list)
    first_seen: str | None = None
    last_seen: str | None = None


class SkillsResponse(BaseModel):
    range: RangeInfo
    skills: list[SkillStat] = Field(default_factory=list)
    total_loads: int = 0


def skill_stats(
    conn: sqlite3.Connection,
    *,
    days: int = 30,
    project: str | None = None,
    now: datetime | None = None,
) -> SkillsResponse:
    """skill 命中排行。session_id 从 tool_calls 关联而来（skill_hits 自己不带）。"""
    start, end = _range_bounds(now, days)
    start_iso, end_iso = to_iso(start), to_iso(end)
    rows = conn.execute(
        """
        SELECT h.skill_name AS skill_name,
               h.tool_name  AS tool_name,
               c.session_id AS session_id,
               COALESCE(a.timestamp, t.started_at, s.recorded_at, s.first_seen_at) AS occurred_at
        FROM skill_hits h
        LEFT JOIN tool_calls c ON c.file_path = h.file_path AND c.ordinal = h.ordinal
        LEFT JOIN api_calls a ON a.file_path = h.file_path AND a.ordinal = h.ordinal
        LEFT JOIN turns t ON t.session_id = c.session_id AND t.turn_id = c.turn_id
        LEFT JOIN sessions s ON s.session_id = c.session_id
        WHERE COALESCE(a.timestamp, t.started_at, s.recorded_at, s.first_seen_at)
              BETWEEN ? AND ?
        """,
        (start_iso, end_iso),
    ).fetchall()
    ...
```

按 `skill_name` 聚合成 `SkillStat`：`loads` 计数、`session_count` 去重、`tool_names` 排序去重、
`first_seen` / `last_seen` 取 `occurred_at` 的最小 / 最大；`total_loads = sum(loads)`；
`project` 过滤沿用 P2.1 的会话白名单写法。

`api/routes/skills.py` 与 `api/routes/context.py` 同构（`Get /api/skills`），并在 `app.py` / `schemas.py` 注册。

## Self-Review（控制器已核对）

- **Spec 覆盖**：6.8 的「skill 名、被加载次数」→ Task 1 与 Task 3；「其说明文本的 token 成本」→ 本计划
  用「命中次数 + 覆盖会话」代替（有意收窄，理由见 Global Constraints）；「加载后该轮的成本变化」→ 明确不做。
- **数据一致性**：`skill_hits` 不带 `session_id`/`turn_id`，一律通过 `tool_calls` 的
  `(file_path, ordinal)` 关联获得，避免猜错归属。
