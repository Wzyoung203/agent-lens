# P1.4a 查询 API（FastAPI）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 P1.2 的 SQLite 投影层包装成一组只读聚合查询 + 少量配置写入的 HTTP 接口，供 P1.4b 的中文仪表盘消费。

**Architecture:** `queries.py` 是纯查询层（只接收 `sqlite3.Connection`，返回 pydantic 模型，零 HTTP 依赖）；`pricing.py` 扩展出「按调用时刻 + 时段选价」的能力；`api/` 是一层薄薄的 FastAPI 路由，只做参数校验、调用 `queries.py`、序列化。生产模式下 FastAPI 顺带托管 P1.4b 的静态构建产物，因此前端与 API 同源。

**Tech Stack:** Python 3.12、FastAPI、uvicorn、pydantic v2、SQLite、pytest、httpx（TestClient 依赖）、ruff、uv。

**Spec:** `docs/superpowers/specs/2026-09-24-agent-lens-design.md`（重点 3.1、6.1、6.4、6.5、6.6、9.1、9.2、9.3、9.4、10、11 节）

## Global Constraints

- Python `>=3.12`。运行期依赖新增 `fastapi` 与 `uvicorn[standard]`；`httpx` 放 dev 组。
- **只读为主**：查询接口绝不写业务表；唯一的写接口是设置页的价目表 / 项目映射 / 保留策略编辑。
- 时间一律 UTC aware；对外输出 ISO8601 文本（`storage.to_iso` 口径），前端负责本地时区换算。
- **成本不落库**（设计文档 6.4）：所有金额都在查询时用价目表计算，因此改价后历史趋势一致重算。
- 所有聚合统计一律对单次 `usage` 求和，绝不读取累计字段（设计文档 4.2）。
- `output_tokens` 已包含 `reasoning_output_tokens`，两者不可相加（设计文档 4.4）。
- 标识符用英文，注释与 docstring 用中文。
- 前端不直连 Langfuse（设计文档 9.1 / 9.3），Langfuse 状态由 API 的 `/api/settings/status` 代为汇报。

## 与设计文档的三处有意偏差（执行前已确认）

1. **价目表增加 `time_window` 维度。** 设计文档 6.4 的「对 P1.4 的两条约束」第 1 条要求先决定时段建模。决定：`pricing` 主键扩为 `(provider, model, effective_from, time_window)`，`time_window ∈ {any, peak, idle}`；查价时按调用时刻判定时段，命中优先，未命中回落 `any`。理由：deepseek 空闲价一律是高峰价的一半，用两行显式记录比在代码里做「除二」的隐式规则更容易被设置页编辑与审计。代价：schema 升到 v3 并需要一次重建表的迁移。
2. **模型名归一化用代码内的别名表，不建新表。** 设计文档 6.4 约束第 2 条要求处理 `deepseek-v4-flash` 这类遗留名。决定：`pricing.normalize_model()` 持有一份常量别名表，查价先归一化再匹配，匹配不到再用原名重试。理由：零新增表、确定性、可单测。代价：用户新增别名要改代码，属已知取舍。
3. **`api_call_view` 增补计费所需列。** 设计文档 6.3 未列视图列清单，但 6.4 的计价需要 provider。决定：schema v3 重建视图，补 `s.model_provider`。代价：视图重建属于 v3 迁移的一部分。

**行为约定（写进测试）：**

- `price_at` 选价顺序：`(归一化名, 按 at 判定的时段)` → `(归一化名, "any")` → `(原始名, 判定时段)` → `(原始名, "any")` → `None`。
- `Pricer.cost_for` 对 `input_tokens == 0 and output_tokens == 0` 的行返回 `0.0`；对查不到价的行返回 `None`。

**口径约定（写进测试）：**

- 窗口是相对 `now` 向前推的天数、含当天，取整到当天 00:00 UTC；比较用 `timestamp >= start AND timestamp < end`。
- `total_tokens = Σ(input_tokens + output_tokens)`；`reasoning_output_tokens` 不再相加。
- `cache_hit_rate = Σcached / Σinput`，分母为 0 时返回 `0.0`。
- `total_cost` 是窗口内可定价调用之和；不可定价调用计入 `unpriced_calls`，不计金额。
- `tool_failure_rate = 失败 tool_call 数 / 有结果的 tool_call 数`。
